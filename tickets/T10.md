# T10 · Connect phase · 15 pts

**Goal:** one multi-hop orchestration across four services.

- `POST /api/orders` flow: gateway → order → auth (validate token) → menu (read price and stock) → menu (reserve) → save with a **server-computed total**.
- Reject with `404` on a missing item, `409` on short stock.
- Ignore any client-sent price entirely.
- Stop menu-service and confirm a clean error, not a hang.
- Run `scripts/verify-T10` and `scripts/run-all`.

**Acceptance:** happy path decrements stock and returns 201; unknown item 404; short stock 409; a client-sent price is ignored; menu-service down gives a clean error.

**Hints:**
1. Validate → read → then write; do not mutate state on a path that will later fail.
2. Compute `total = quantity * price` on the server, never from the request body.
3. Multi-hop orchestration is the shape of most real backend work — read, then write, across two services.
